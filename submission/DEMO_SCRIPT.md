# LAST WORDS — 60-Second Demo Script

## Non-negotiable capture rule

Every product shot must be captured from the working build. Do not use a
Figma frame, generated interface, simulated counter, manually replaced shader
text, or staged database response. Editing may crop, zoom, place two real
browser captures side by side, add captions, and shorten waiting time. Label
any time compression.

Target: **60.0 seconds, 1280×720, 30 fps, H.264, readable without sound.**

## Before recording

- Use the final public build or an identical local build with a disposable
  demo database. Never damage the production edition just to stage a shot.
- Prepare two clean browser windows, A and B, on the same shared instance.
- Window B must already be open before the sacrifice so its later update
  proves synchronization.
- For the ending shot, prepare a separate disposable edition with nineteen
  laws genuinely removed through the same data model. The twentieth sacrifice
  must use the normal public interaction path.
- Confirm the shader panel shows an actual changed constant, a higher build
  number, and `COMPILE PASS`.
- Confirm the completed edition is visible in the archive and the next world
  receives a new number.
- Record the whole interaction first. Add captions and crops only afterward.
- If the deployment is using the deterministic fallback, caption it as
  `LOCAL FALLBACK RESPONSE`; do not label that response as model-generated.

## Recording notes

### Make the proof legible

- Hold every technical receipt for at least 1.5 seconds.
- The law value changing to zero, build increment, and `COMPILE PASS` must be
  readable at 720p without pausing.
- Keep the organism visible during at least part of the shader proof so judges
  connect code change to sensory change.
- Use one pointer highlight only if necessary; do not cover the selected word
  or changed constant.

### Make the emotion legible

- Do not open with architecture or a terminal.
- Let the hover preview breathe before the click.
- Let the final reply finish before cutting to the archive.
- Keep the last three seconds quiet and uncluttered. The final sentence is the
  thesis, not a feature list.

### Sound

- Captions must carry the complete argument because judges may watch muted.
- Use the artwork's real generated mutation tone if it records cleanly.
- Do not add copyrighted music.
- If narration is recorded, keep it under the exact optional voiceover above
  and duck the interface tone rather than removing it.

## Required evidence checklist

- [ ] Initial world number and build are visible.
- [ ] Reversible hover preview is visible.
- [ ] One normal sacrifice is shown from selection through impact.
- [ ] The actual changed law and value are readable.
- [ ] A real shader compile pass is readable.
- [ ] A second untouched browser receives the same mutation.
- [ ] The AI/fallback reply and vocabulary burn are shown honestly.
- [ ] `/remains` changes on screen.
- [ ] The twentieth real law ends the disposable edition.
- [ ] The completed edition remains in the real archive.
- [ ] The successor has a different WORLD number.
- [ ] No screen in the video promises a feature absent from the public build.
